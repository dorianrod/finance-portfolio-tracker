# API, schemas, cache, security and client-state review

Eligible query/schema/atom/service targets are explicitly enumerated in source-patterns.json and rule-targets.json. Every domain query hook was read with its shared source options. Common CSV sources validate through parseCsv/parseOptionalCsv and module-level schemas. Parameterless reads have no fake request object. Filtered-history and asset-IRR request modules validate/serialize request fields, validate JSON responses and propagate AbortSignal; static demo guards choose released transport behavior before starting conditional work. Independent CSVs use Promise.all; dependent aggregation waits only for its source. Select transforms validated data, not the TanStack result object. Cached observers use skipToken.

All query keys are derived from the typed portfolioQueryKeys registry, with sorted selection and Date inputs. No mutation/optimistic/invalidation capability exists. Required Suspense reads live in sibling consumers under DashboardSourceBoundary, with cache-observed loading/error union in the persistent shell; optional cached/filtered reads keep previous data and expose placeholder/updating states. App retains navigation outside slow content boundaries. Existing source-boundary tests cover independent source startup and retained shell interactions.

Schemas keep finite numeric amounts and real calendar Dates, explicitly justify missing returns/metadata, normalize categories at the boundary, and preserve vendor display names. Logic branches on closed domain unions, not free status strings. Optional CSV absence is handled by the common HTTP/CSV layer, and normalized errors reach useFormatErrorMessage. No hook casts a Yup result to silence entity drift. Domain support types called Raw already contain validated numbers/Dates; they are not leaking wire strings.

ExternalLink validates http(s), provides rel=noopener noreferrer and uses readable text for malformed sources. No window.open, auth/logout, bearer file endpoints or object-URL lifecycle exists.

Atom modules own only client filters, search, sorting, row expansion, metric/date selection and primitive interaction input. They use concern files and direct imports; no store index barrels or entity cache mirrors. Source/action/consumer calls in the pattern inventory verify functional updates and module-scope identity. ScopeProvider isolates repeated primitive/card state. Theme uses atomWithStorage with validated custom storage, getOnInit, unique key, caught access/read/write/removal failures and change-event validation. Other filters are intentionally session-local. Effect hooks own theme, delayed dismissal, preview reset, panel dismissal and playback synchronization; timers/listeners clean up. Virtual-list and chart-width local state is visual instance state, not a business-state facade.
