# Tests, tool calibration and quality review

The initial concurrent baseline timed out three tests (two 5s architecture probes and one 60s fixture inventory), with no assertion failures. Running the unchanged normal npm test alone passes all 277 application suites/2346 tests and all 33 packaged suites/756 tests; baseline-tests-isolated.log preserves that evidence. No timeout configuration or test assertions were weakened.

Actual-config integration suites reject invalid neighbors and accept valid ones for roles, folder/import ownership, helper/service boundaries, browser effects, formatter hooks/fallbacks, aliases/reexports/dynamic imports, scoped atoms, nullability, query naming/data aliases, public APIs, typed safety/deprecations, ARIA/style/slots, translation dates/numeric strings, test fixtures/assertions/network/semantic queries and suppression metadata. These are the isolated calibration probes for the selected deterministic families, with intended rule IDs/severities in the tests; passing lint alone was not used as calibration. See tests/eslint and baseline-tests-isolated.log. Packaged tests also cover cycle graph edges and script limits.

Source fixture candidates and exclusions were inspected against their real consumers and owning mocks. The 15 ledger decisions are explicit reset/filter arguments, reliability scope/count policy inputs, single-call selection parameters, nullable compared-value scenarios and raw JSON network responses. They are not reusable fixture baselines. Domain defaults live in typed deterministic owning mocks; controlled-clock tests are separate from fixtures. No internal module mocks or skipped application assertions were found. Per-test QueryClient/Jotai providers isolate query and atom tests; API regressions stub the transport and run real schemas. Meaningful nominal/missing/error/edge assertions remain separate from sibling-test presence.

Formatting and normal lint pass. There are 142 inline tracking warnings plus one review-shared-feature-sharing warning. The latter concerns common account filter options passed by the shell to multiple portfolio capabilities; README and useBuildDashboardSourceData/useDashboardHistory/position grouping supply consumer evidence. Existing exception dates/technical justifications, rule-off entries and configured excludes were not renewed. The 143 ceiling has no spare capacity. New code must add no bypasses.

No deprecated annotated API, public-hook factory, no-op product action, leaked unhandled promise or new namespace ref wrapper was found by checks and source pattern review. Technical CSV field names such as secteur are established external vocabulary, not new non-English code. Existing JSDoc explains identity/schema/lifecycle intent; ten decision comments are supported.
