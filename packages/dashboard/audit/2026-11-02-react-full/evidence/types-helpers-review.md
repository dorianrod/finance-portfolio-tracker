# Type and helper semantic review

Typed compiler/lint checks establish declared shapes and module dependencies; ownership and meaning were checked through the source/caller inventory. All 32 support-type entries in the architecture output are component props, chart renderer payloads, explicit local helper input/output contracts or their sub-shapes: FundDiagnosticsRow, CombinedReliabilityInput, ScopedFundQualityData/FundExposurePercentages, ManualPriceOverridesProps, Trend/HoldingTooltipProps, VirtualExposureItem, BuySellDotProps, HoverChartDataPoint/RollingReturn, PositionGroupTotal, FundStatusIndex/Entry, OverviewPeriod/Windows/ComparedMetric/ValuePoint/ConcentrationPoint/ConcentrationComparison/Comparison, IrrKpiProps, AccountTreeProps, AccountTypeTooltipPayloadItem/LabelPosition, YearLabelPlacement, ScopeBadge, AccountFilterRow, RawCashRow, RawSavingCapacityRow/ByAccountRow and HistoricalSnapshot. Some entries share files; none creates a separate independently maintained business entity outside its owner. Existing `.types.ts` output modules are permitted support contracts. Do not move them solely because the inventory emitted them.

Financial amounts/weights remain numeric; genuinely absent observations have documented nullable types. Account categories/status decisions use closed unions. Dates originate in schemas; new Date from grouped numeric timestamps, month arithmetic and UTC date calculation is derived domain data, not response re-coercion. Chart/control month keys are technical strings. AccountTypeChartPoint composes the entity and adds prepared reporting/visual fields rather than copying source shape.

Helpers use exactly transformers/formatters/presenters. Dependency checks cover all modules; semantic review distinguished business selection/aggregation from visual series selection and geometry. Aggregations mutate fresh maps/arrays rather than caller collections; use toSorted/toReversed/copies preserve incoming order. Existing tests exercise source-label collisions, own-property dictionaries, duplicate-ID precedence, grouping immutability, null/empty financial inputs and unknown metadata. Repeated keyed lookups use maps/indexes; remaining find calls select one item or tiny tooltip/theme arrays, so indexing adds no justified requirement. resolveAssetName selects canonical source identity stored in derived domain data; useFormatAssetLabel owns displayed text. Source labels are not translated aggregation keys.

F-001 covers three independently usable **domain-value to label** maps: short allocation dimensions, title-case quality dimensions and reliability status. They should have nullable, fallback-owning, context-reading formatter hooks. Static section/navigation/column headings and scope-specific explanatory UI narratives remain component/presenter configuration; they are not an alternative implementation of a reusable unit label. Existing useFormatDataQualityDimension owns lowercase labels; extend it with title style rather than duplicate it. Reliability tones are valid visual mappings once labels are removed. The narrow owners are fixed by current consumers and vocabulary; no feature restructuring is needed.

New formatter APIs are already protected by configured formatter-contract/helper-module-contract/type checks. The old semantic misplacement is not diagnosed by those checks; adding a blanket ban on translation records would reject valid headings, so semantic ownership review remains necessary. Phase 2 will add exhaustive, missing-value and provider-specific tests instead of an unsound generic heuristic.
