# Shared ownership review — 26 October 2026

The production import graph was reviewed after splitting public exports. Seventy-one modules moved to their business owners: scope selection, wealth, allocation, position inspection, fund look-through and quality assessment. Theme persistence and synchronization moved to the application shell. No sibling dependency or shared-to-child import was introduced.

The remaining 66 findings concern common source inputs delivered through application props or the common navigation protocol. Each exemption applies only to the reported Program line and names the consuming capabilities. These reviewed exemptions now target the `local/review-shared-feature-sharing` warning for indeterminate sharing. `local/shared-feature-usage` still reports exclusive one-feature ownership and unused shared modules as errors, including in these files. Recheck the following evidence when changing their consumers.

The source path is `useDashboardViewModel` → feature-owned `useDashboardWealth`, `useDashboardPerformance`, `useOverviewComparison`, `useDashboardQuality` and `usePortfolioPositions` → `DashboardContent` entry props. Filtered history is shared by the first three analyses. Savings input feeds wealth and overview. Raw allocation feeds diversification and assessment. Fund input feeds holdings, diversification, overview and assessment. Source schemas and query options belong to those same common input protocols; they do not implement a child capability's interpretation. Account labels also reach `FilterScopeBadges` through the existing React Query cache.

Anomalies are jointly owned by the two data-quality children: assessment filters and summarizes them, while errors displays the detailed tables. Navigation connects overview links with the application's portfolio entry points and is shared infrastructure. Application files are evidence of the data path, not additional business features.

## Common diversification inputs reviewed in the full audit

Three additional scoped exceptions concern
`diversification/shared/helpers/filters/prepareDiversificationScope.ts` and its
`scopeDiversificationData/scopeRawAllocationData.ts` and
`scopeDiversificationData/excludeNonApplicableAllocationData.ts` dependencies.
`DiversificationCharts` distributes the applicable positions to concentration and
the scoped allocation rows to allocation; both analyses share the availability
gates derived from that scope. These are parent-owned common inputs rather than
category selection or concentration calculations. Application wrappers are not
counted as feature consumers. This path was rechecked in
[DashboardDiversification.feature.tsx](src/app/DashboardDiversification.feature.tsx)
during the 2026-10-27 ESLint exception review.
